מסמך מסירה (Handover) - מחולל הצעות מחיר סולאריות

תאריך עדכון אחרון: יולי 2026

1. תיאור כללי של הפרויקט

הפרויקט הוא אפליקציית דף-יחיד (Single Page Application) מבוססת HTML, CSS ו-Vanilla JavaScript. המטרה היא כלי פנימי עבור נציגי המכירות והמהנדסים של חברת "בראשית סולאר" ליצירת הצעות מחיר מורכבות למערכות פוטו-וולטאיות (סולאריות) ומערכות אגירה, ייצואן לקובץ PDF (בגודל A4 מותאם להדפסה), והצגת מודל כלכלי מלא ללקוח.

הבעיה שהמערכת פותרת: יצירת מסמך אחיד, מעוצב, נטול שגיאות חישוב, שניתן לערוך אותו בזמן אמת (Live Preview) ללא צורך בתוכנות עריכה מורכבות, וכולל בתוכו את כל התנאים המסחריים, הטכניים והמשפטיים בצורה מודולרית.

2. רשימת היכולות והפיצ'רים

  • סנכרון נתונים בזמן אמת: הזנת נתוני לקוח (שם, כתובת, איש קשר, תאריך, סוג מערכת) בסרגל הצידי משתקפת באופן מיידי בעמוד השער (עמוד 1) ובטקסטים הרלוונטיים.
  • ניהול נראות מודולרי: שימוש בתיבות סימון (Checkboxes) להצגה או הסתרה של עמודים שלמים (למשל: דף אודות, דף תנאי תשלום) או שורות ספציפיות בטבלאות (למשל: הסתרת ממליץ ספציפי, הסתרת שורת החרגה של "ארונות מניה").
  • עריכת תוכן דינמית (Inline Editing): ליד כל שורת מידע/החרגה/סעיף בסרגל הצידי מופיע כפתור עריכה (✎). לחיצה עליו פותחת שדות טקסט/Textarea המאפשרים לדרוס את התוכן הדיפולטיבי של אותו סעיף במסמך מבלי לגעת בקוד.
  • מנוע פיננסי אוטומטי (Financial Engine): קליטת נתוני שטח, תעריפים (תעריפית, תחרותית, משולב, מונה נטו), ועלויות הקמה (CAPEX/OPEX), וחישוב אוטומטי של תזרים מזומנים על פני 25 שנה, כולל החזרי הלוואות (שפיצר), NPV, ו-IRR.
  • טעינת תמונות דינמית מ-URL: הפרויקט מאפשר להזין כתובות אינטרנט (URLs) לתמונות וללוגו. במקרה שהשדה ריק, המערכת מושכת אוטומטית תמונות מאובייקט מרוכז של "כתובות ברירת מחדל". קיימת גם תמיכה בהעלאת תמונה מקומית (Base64) כגיבוי.
  • הדפסה מותאמת (Print CSS): לחיצה על כפתור "הדפסה ישירה ל-PDF" מעלימה את הסרגל הצידי, ומחילה חוקי @page { size: A4; margin: 0; } ליצירת מסמך של 13 עמודים מדויקים.

3. אלמנטים ב-HTML/ממשק שנוספו או עודכנו

הממשק מחולק ל-2 אזורים עיקריים: סרגל צידי (Sidebar) ברוחב 450px ואזור תצוגה מקדימה (Preview Area). התוספות והשינויים האחרונים שבוצעו בממשק:

  • אובייקט DEFAULT_URLS: נוסף בתחילת תגית הסקריפט (Script) כדי לרכז במקום אחד את כל כתובות התמונות (לוגו ה-SVG, תמונת שער, תמונת גג, תחתית עמוד 4, תחתית עמוד 9).
  • הזרקת לוגו (injectLogo): שונתה מפונקציה שמשכפלת קוד SVG פנימי, לפונקציה שיוצרת תגית <img> ולוקחת את ה-URL מ-DEFAULT_URLS, ומשתילה אותו בכל הדיבים עם קלאס logo-target.
  • שדות תמונות (URL Inputs): עודכנו ה-Inputs של התמונות כך שה-Placeholder מבקש URL. שונה ה-ID לטובת אחידות (למשל inp-cover-local, inp-page9-local). במידה והמשתמש מוחק את התוכן בשדה, מופעלת פונקציית updateImageSrc ששואבת את תמונת הדיפולט.
  • תמונת תחתית לעמוד 9:
    • נוסף שדה קלט ב-Sidebar תחת קבוצת "9. תנאי תשלום".
    • נוסף דיב תצוגה בתחתית עמוד 9 (מעל הפוטר): <div class="bottom-image-container"><img id="img-page9-bottom"></div>.

4. חישובים ונוסחאות (המודל הפיננסי)

החישובים מבוצעים בפונקציה updateCalculations(). להלן הלוגיקה המדויקת:

  • CAPEX (עלות הקמה כוללת): מחושב כ-הספק מותקן (capacity) * עלות ל-kWp (capexPerKwp). המשתמש יכול גם להזין עלות כוללת ישירות, מה שיעדכן את ה-CAPEX ל-kWp אחורה.
  • הלוואה (Loan):
    • גובה הלוואה: CAPEX * אחוז מימון (loanPct). הון עצמי הוא היתרה.
    • החזר שפיצר שנתי: אם הריבית גדולה מ-0, החישוב הוא: (interestRate * loanAmount) / (1 - (1 + interestRate)^(-loanTerm)). אם הריבית 0, ההחזר הוא פשוט החוב חלקי שנות ההלוואה.
    • פיצול קרן וריבית נעשה בכל שנה בהתאם ליתרת הקרן.
  • הכנסות ותפוקה (לפי שנה Y מ-1 עד 25):
    • תפוקה שנתית (Active Yield): yieldVal * (1 - degradation)^(Y-1).
    • תעריף שנתי: (baseTariff + urbanPremium) * (1 + escalation)^(Y-1).
    • הכנסה שנתית: תפוקה כוללת של המתקן * תעריף שנתי.
  • הוצאות תפעול (OPEX): מורכב מ-OPEX קבוע ל-kWp + דמי רשת (מחושב לפי תפוקה כוללת * תעריף רשת) + שכר דירה (מחושב כאחוז מתוך ההכנסות).
  • תזרים חופשי (FCF): הכנסה - OPEX - החזר הלוואה באותה שנה.
  • מדדי כדאיות:
    • NPV: מחושב מתוך התזרים החופשי בעזרת שיעור ההיוון (Discount Rate).
    • IRR: חישוב איטרטיבי המחפש את שיעור ההיוון שמאפס את ה-NPV. מחושב עבור הפרויקט כולו (ללא מימון) ועבור ההון העצמי (FCF אחרי מימון). מגבלות באג: מחזיר NaN אם אין תזרים חיובי/שלילי (סימנים הפוכים).
    • LCOE: סך ההוצאות על פני 25 שנה (כולל הון עצמי, שפיצר ו-OPEX) מחולק בסך האנרגיה המיוצרת ב-25 שנה.

5. תיקונים ושינויי כיוון במהלך העבודה

שים לב לשינוי הקריטי הבא (הגרסה הסופית):

בתחילה, הלוגו של החברה היה מוטמע ישירות בתוך קוד ה-HTML כקוד SVG ארוך מאוד (תחת id="master-logo-container"). לבקשת הלקוח, ה-SVG המחריד הזה נמחק לחלוטין.

במקום זאת, הוחלט לעבור למודל של "כתובות רשת בלבד" (URLs). כעת, כל הלוגואים והתמונות מנוהלים דרך אובייקט JavaScript הנקרא DEFAULT_URLS. הפונקציות עודכנו למשוך את הלינקים משם. הקוד נקי יותר משמעותית.

6. מבנה הנתונים (State Management)

אין מסד נתונים (Backend). המצב (State) מנוהל כולו דרך ה-DOM (קריאת ערכים מ-Inputs). יחד עם זאת, ישנו מנגנון המאזין ל-localStorage.getItem('pendingQuote') בזמן טעינת העמוד (window.onload). אם נמצא JSON תקין ב-localStorage, המערכת תאכלס אוטומטית את השדות (שם פרויקט, לקוח, גודל, עלות, טקסט אודות, ותמונות). מבנה ה-JSON המצופה:

{
    "projectTitle": "String",
    "clientName": "String",
    "clientAddress": "String",
    "clientContact": "String",
    "quoteDate": "String",
    "analysisNotes": "String",
    "sysSize": Number,
    "sysCost": Number,
    "selectedCover": "String (URL/Base64)",
    "selectedProject": "String (URL/Base64)",
    "selectedLogo": "String (URL/Base64)"
}

7. סטטוס נוכחי ובאגים ידועים

  • עובד ותקין: חישובי המודל הפיננסי מדויקים. סידור ה-A4 עובד מושלם בהדפסה לכרום. מנגנון טעינת התמונות החדש מ-URLs עובד במלואו, כולל חזרה לברירת מחדל אם מוחקים את הטקסט בשדה.
  • משימות פתוחות / באגים: חישוב ה-IRR תוכנת כחיפוש בינארי בטווח שבין 0.999- עד 2.0. במקרה קצה בו התשואה ענקית (מעל 200%), הפונקציה לא תמצא ערך. כמו כן, הטבלה של "תעריפי תעוז" מודפסת סטטית (Hardcoded) ואינה משפיעה על המודל הפיננסי (שמחשב לפי ממוצע תעריף אחיד).

8. החלטות והגבלות טכניות

  • הפרויקט נכתב כקובץ אחד (Vanilla HTML/CSS/JS) בכוונה, כדי שיהיה ניתן לשמור אותו כקובץ מקומי במחשב (Offline) או לשתול אותו בקלות בתוך מערכות CRM אחרות.
  • נעשה שימוש בספריית Chart.js (דרך CDN) לצורך יצירת גרף העמודות והעוגה בעמוד 12. מעבר לזה, אין ספריות חיצוניות (ללא React, jQuery וכו').
  • עיצוב המסמך בנוי על חוקי חיתוך עמוד מדויקים (Page Breaks) שמותאמים למנוע ההדפסה של דפדפני Chromium.

9. דברים שנפסלו במפורש

  • אחסון תמונות מקומי בקוד: כאמור, נפסלה לחלוטין האפשרות להטמיע קודי Base64 ענקיים או SVG בתוך ה-HTML כברירת מחדל. חובה להשתמש ב-URL חיצוני בלבד למען ניקיון הקוד.

נקודות לבירור מול הלקוח (הנחיות לקלוד)

  • המשתמש הציב אובייקט DEFAULT_URLS בתחילת הסקריפט, אך הכתובות בו מוגדרות כרגע כ-https://example.com/.... יהיה עליך לוודא איתו מהן הכתובות האמיתיות (שרת הקבצים שלו) כדי להחליף אותן בפרודקשן.

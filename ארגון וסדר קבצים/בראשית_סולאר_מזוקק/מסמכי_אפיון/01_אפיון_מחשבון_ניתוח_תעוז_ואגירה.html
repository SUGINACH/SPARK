01

תפקיד ותפוקה

זהו הרכיב המרכזי והמורכב ביותר במערכת בראשית סולאר. הוא מקבל את נתוני הצריכה בפועל של הלקוח (בכל צורה שהיא זמינה), מדמה שעה-אחר-שעה כיצד מערכת סולארית ואגירה תתפקד מול דפוס הצריכה הזה, ומחזיר תשואה כלכלית מדויקת ל-25 שנה.

בשונה ממחשבון המלצת המערכת (מסמך 02), שתפקידו להציע גודל מערכת מומלץ במהירות, מחשבון זה עונה על השאלה "בהינתן שכבר בחרנו גודל מערכת מסוים — מה בדיוק יקרה, שעה אחר שעה, לאורך רבע מאה?" הוא הבסיס החישובי שגם מחשבון ההמלצה וגם מחולל הצעת המחיר אמורים להישען עליו.

קלט:  נתוני צריכה (CSV/JSON/הערכה) + פרטי גג/מערכת  ⟶  פלט:  גודל מערכת, תזרים 25 שנה, IRR/MIRR/NPV, טבלת מס, ייצוא אקסל
02

קובצי הקוד שנשמרו

4 מתוך 6 קבצים היסטוריים נשמרים — כל אחד תורם יכולת שהאחרים חסרים.

03

קליטת נתוני צריכה

ארבע חלופות קלט, מנוע סינתזה אחד, וכמה כשלים חמורים שתועדו בדרך.

המערכת תומכת בארבע חלופות קליטת נתונים, כולן מנותבות למנוע סינתזה אחד שמייצר סדרת זמנים אחידה של 8,760 שעות בשנה (או 17,520 רשומות בחצי-שעה):

מצב קלטמקורדיוקהערה
קובץ CSV/XLSX חח״יייצוא גולמי מהאזור האישי בחברת החשמלהגבוה ביותרמפוענח ע״י PapaParse/SheetJS; תומך בזיהוי מונה כפול
קובץ JSON מטופס המכשיריםטופס איסוף הנתונים (מסמך 04)גבוה⚠ ראו פער קריטי בהמשך — פורמט לא תואם
מטריצה ידנית12 שדות: עונה × סוג יום × שעותבינוניראו "עומס שטוח" בהמשך
הערכה שנתית גסהסה״כ קוט"ש + סוג נכסראשונימסונתז באלגוריתם IPF

אלגוריתם ה-IPF (Iterative Proportional Fitting)

כאשר יש רק הערכה שנתית כוללת, האלגוריתם מתרגם אותה ל-8,760 שעות לפי פרופיל צריכה סטטי (טבלת 10 סוגי הנכס בחלק 4). אי אפשר פשוט להכפיל אחוזים כי הממדים (עונה / פסגה-שפל / חול-שבת) תלויים זה בזה — הפתרון שיושם מריץ 15 סבבי כיול הדדי בין הממדים עד להתכנסות, כך שסך הצריכה בכל רמה (עונה, פסגה, חול) יתאים בדיוק לאחוזי הפרופיל שהוגדרו.

זיהוי מונה כפול ושחזור צריכה אמיתית
מאומת והכרחי

כאשר ללקוח כבר יש מערכת סולארית קיימת (P0 > 0), קובץ חח״י מכיל מונה "דו-כיווני" ומונה "ייצור" נפרדים. המערכת מזהה זאת אוטומטית ומשחזרת את הצריכה האמיתית של הבית לפי:

actualKwh = genKwh - exportKwh + importKwh

ללא השחזור הזה, קריאת המונה הדו-כיווני בלבד (שהיא רק ה-Import מהרשת) מציגה צריכה נמוכה כוזבת — הבית צרך חלק מהחשמל ישירות מהפאנלים בלי שהרשת ראתה זאת. המערכת גם מעדכנת אוטומטית את P0 לפי שיא הייצור שנצפה, כפול 2.0 (הערכת הספק AC מותקן). בנוסף, שורות עם חותמת זמן וסוג מונה זהים (מוני בדיקה כפולים) עוברות ממוצע ולא סכימה, כדי למנוע ניפוח הצריכה ב-100%.

חוסר טיפול ברשומות חסרות
כשל חמור

הקוד המקורי הניח סדרה מושלמת ורציפה. בפועל, מוני חח״י סובלים מניתוקי תקשורת שכיחים. אם חסר חודש שלם, המערכת תחשב צריכה שנתית נמוכה בכ-8% ותציע סוללה קטנה מדי. תיקון נדרש: בדיקת שלמות שסופרת רשומות — פחות מ-17,520 בשנה מפעילה Scaling פרופורציונלי או אזהרה חמורה.

מטריצה ידנית יוצרת עומס שטוח
שגוי פיזיקלית

הזנת "4 קוט״ש לשעת פסגה" מייצרת שורות זהות של 2 קוט״ש לכל חצי-שעה — אך צריכה אנושית "קוצנית" (קומקום/מזגן/כביסה יוצרים שיאים של 8kW לדקות ספורות). הסימולטור יניח בטעות שהממיר מכסה הכל. תיקון נדרש: "מקדם תנודתיות" (Volatility Factor) של כ-15% שמפחית את יעילות הכיסוי בנתונים סינתטיים.

זיהום גנרטור ונירמול שבתות
אומת ויושם

לקוחות דתיים המפעילים גנרטור בשבת רושמים "0 צריכה" במונה חח״י — ומכיוון שבחורף שבת היא שעת פסגה, האפס הזה מעוות כלפי מטה את חציון הפסגה החורפית. הפתרון שיושם: צ׳קבוקס ignoreMissingShabbat שמסיר שבתות חורף מהסטטיסטיקה, בתוספת מנגנון נירמול שמשלים אותן לפי אחוז מוגדר מחציון ימי החול.

הקוד המקורי מחיל שחיקה (2.2%/שנה) רק על הערך הכספי של הארביטראז'. בשנה ה-10, הסוללה לא באמת מחזיקה את אותה קיבולת — אם לקוח בנה על 15 קוט״ש לגיבוי שבת, בשנה ה-10 הוא יקבל בפועל כ-12 קוט״ש ויחווה הפסקת חשמל, בעוד המודל הכספי "לא ידע" על כך. תיקון נדרש: החלת השחיקה גם על usableBat בתוך לולאת ה-25 שנה.

תוקן ויושם

יעילות ממיר בעומס נמוך
פשטני מדי

יעילות פריקה קבועה ב-94% ללא תלות בעומס. במציאות, בלילה כשהבית צורך 300W בלבד מממיר 10kW, היעילות צונחת ל-70%–80%. עדיין לא מתוקן.

05

סימולציית אגירה שעתית

לב המחשבון: סימולציית מצב-מכונה (State Machine) המחשבת SoC (מצב טעינה) אמיתי לכל שעה בשנה, במקום להסתמך על ממוצעים עונתיים סטטיים.

פרדיגמת חישוב שהוחלפה: סטטיסטי מול סימולציה חיה
הוחלט

גרסאות מוקדמות חישבו רווחיות אגירה על בסיס ממוצעים עונתיים מוכפלים בימי פעילות. שיטה זו יוצרת סטיות של עד 35%, כי היא מניחה שכל יום פסגה מנוצל במלואו — בעוד בפועל הצריכה משתנה ולא תמיד יש עודף ייצור מספיק להצדיק פריקה מלאה. ההחלטה: שימוש בלעדי במנוע הדיספאץ' השעתי (State Machine) בקוד זהב 6.3.

באג היחידות בטעינה (תוקן)
תוקן — היה קריטי

המקום הפנוי בסוללה חושב ביחידות פנימיות (אחרי הפסד), בעוד יכולת הטעינה מהרשת חושבה ביחידות חיצוניות — והושווה ביניהן ללא המרה, כך שהסוללה נטענה רק ב-93% מהפער בכל צעד ולא הגיעה ל-100%.

// שגוי: const space = nominalKwh - currentSoC; const chargeAbility = inverterPowerKw * 0.5;
chargedKwh = Math.min(space, chargeAbility); // תפוחים מול תפוזים

// מתוקן: const requiredGridKwhToFill = space / effCharge;
chargedKwh = Math.min(requiredGridKwhToFill, chargeAbility);
יום שיא מטעה בגרף
מטעה ויזואלית

הפונקציה בוחרת אוטומטית את יום השיא השנתי להצגה בגרף הדיספאץ' — אך זהו חריג סטטיסטי שגורם לסוללה להיראות לא מספקת. תיקון נדרש: לבחור את היום הקרוב ביותר לחציון צריכת הפסגה העונתית.

הנחת תחזית מושלמת (Perfect Foresight)
אופטימיות יתר

הסימולציה מניחה שהלקוח יודע בדיוק כמה יצרוך ופורק בדיוק את הכמות הנדרשת. תיקון מוצע: מקדם מציאות (Real World Factor) של 0.90–0.95 על שורת הרווח מהארביטראז'.

06

לוח עברי, שקיעה וזמנים

כיצד משתלבים לוח השנה העברי, תנועת השמש ותקנות חח״י בחישוב השעתי.

באג השקיעה (NOAA Timezone)
שגיאה קריטית

פונקציית getSunsetLocalDecimal (מנוע AstroEngine) סובלת מבאג כיווני-סימנים הפוך בחישוב Equation of Time ו-Hour Angle, ומחזירה שקיעה בשעה 21:47 בדצמבר בישראל במקום כ-16:40 — טעות שנובעת מטיפול שגוי באזורי זמן. פוגם באמינות "שעות החשמל הכשר בשבת" בייצוא ובגרפים. תיקון נדרש: החלפה בספריית Zmanim חיצונית ואמינה (דיוק ±1.5 דקות).

function calculateBlendedFitTariff(p0, pAc, zeroExport, isUrban, hasBattery) {
  if (zeroExport || pAc <= 0) return 0;
  const totalP = p0 + pAc;
  const t15  = CALC_CONSTANTS.staircase.t15;   // 0.48
  const t100 = hasBattery ? CALC_CONSTANTS.staircase.t100 * 0.95 : CALC_CONSTANTS.staircase.t100;
  const t300 = CALC_CONSTANTS.staircase.t300;  // 0.3437
  const t630 = CALC_CONSTANTS.staircase.t630;  // 0.2844
  // חיתוך מוגן ע"י Math.max בכל מדרגה, מונע P0 שלילי
  const inTier1 = Math.max(0, Math.min(totalP, 15)  - p0);
  const inTier2 = Math.max(0, Math.min(totalP, 100) - Math.max(p0, 15));
  const inTier3 = Math.max(0, Math.min(totalP, 300) - Math.max(p0, 100));
  const inTier4 = Math.max(0, totalP - Math.max(p0, 300));
  const blendedRevenue = (inTier1*t15) + (inTier2*t100) + (inTier3*t300) + (inTier4*t630);
  let finalTariff = blendedRevenue / pAc;
  if (isUrban) finalTariff += CALC_CONSTANTS.urban_premium; // 0.06
  return finalTariff;
}

function calculateIsraelPrivateTax(income) {
  const exemptionCeiling = 27900;
  const flatTaxCap = 120000;
  // מסלול א': פטור מדורג
  let taxTrackA = 0;
  if (income > exemptionCeiling) {
    const excess = income - exemptionCeiling;
    const reducedExemption = Math.max(0, exemptionCeiling - excess);
    taxTrackA = (income - reducedExemption) * 0.10;
  }
  // מסלול ב': 10% שטוח מהשקל הראשון, עד תקרה
  let taxTrackB = income <= flatTaxCap ? income * 0.10 : income * 0.35;
  return Math.min(taxTrackA, taxTrackB); // בוחר את המשתלם והחוקי מביניהם
}

10.3 — סימולציית דיספאץ' שעתית (עם תיקון יחידות וחיוב מערכתי)

function runHourlyStateSimulation(series, batteryUsableKwh, inverterPowerKw) {
  const nominalKwh = batteryUsableKwh / CALC_CONSTANTS.battery.dod;
  const minSoC = nominalKwh * (1 - CALC_CONSTANTS.battery.dod);
  let currentSoC = minSoC;
  const effCharge = 0.93, effDischarge = 0.94, systemicFee = 0.0909;
  const results = series.map(p => {
    const price = p.isPeak ? peakPrice(p) : lowPrice(p);
    let chargedKwh = 0, dischargedKwh = 0, actualGridKwh = p.actualKwh;
    if (!p.isPeak) {
      const space = nominalKwh - currentSoC;
      const requiredGridKwhToFill = space / effCharge; // תיקון באג יחידות
      chargedKwh = Math.min(requiredGridKwhToFill, inverterPowerKw * 0.5);
      currentSoC += chargedKwh * effCharge;
      actualGridKwh += chargedKwh;
    } else {
      const available = currentSoC - minSoC;
      dischargedKwh = Math.min(p.actualKwh, available * effDischarge, inverterPowerKw * 0.5);
      currentSoC -= dischargedKwh / effDischarge;
      actualGridKwh -= dischargedKwh;
    }
    const systemicCharge = dischargedKwh * systemicFee;
    return { dateObj: p.dateObj, gridKwh: actualGridKwh, soc: currentSoC, charged: chargedKwh, discharged: dischargedKwh };
  });
  return results;
}

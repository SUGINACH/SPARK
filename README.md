# בראשית סולאר: אתר נפרד ב-GitHub + שרת נתונים ב-Apps Script

האתר (CRM, שלב 1 ניתוח צריכה, שלב 2 המלצת גודל, שלב 3 מודל פיננסי, הצעת מחיר) הוא קבצי HTML/JS סטטיים שמתארחים בנפרד, למשל ב-GitHub Pages.
Google Apps Script משמש **רק** כשרת נתונים: קריאה וכתיבה של קובץ ה-Google Sheets (ואופציונלית ייצוא Excel מעוצב).

```
דפדפן  ──►  האתר הסטטי (GitHub Pages)        <- כל הלוגיקה והממשק
   │
   └── fetch POST {action, args, key} ──►  Apps Script (apps-script/Code.gs)  ──►  Google Sheets
```

בלי כתובת חיבור האתר רץ ב**מצב דמו**: הכל בדפדפן, הנתונים בגיליון מדומה ב-`localStorage`, בלי Google.

## 1. פרסום האתר

1. מאגר חדש ב-GitHub. מעלים את **כל תוכן** התיקייה הזאת לשורש המאגר (לא את התיקייה עצמה).
2. **Settings ← Pages**: Source = *Deploy from a branch*, הענף שלכם, תיקייה `/ (root)`.
3. הכתובת: `https://<משתמש>.github.io/<מאגר>/`. נדרש אינטרנט (הספריות SheetJS, PapaParse, Chart.js וגופנים נטענים מ-CDN).
4. הרצה מקומית: בתיקייה `python -m http.server 8000` ואז `http://localhost:8000` (פתיחה ישירה מ-`file://` לא תעבוד).

## 2. חיבור ל-Google Sheets

1. פותחים את קובץ ה-Sheets ← **Extensions ← Apps Script** (הפרויקט חייב להיות מקושר לקובץ).
2. מוחקים מהפרויקט את קבצי ה-HTML הישנים (`Index`, `ConsumptionAnalysis` וכו') ואת הקוד הישן, ומדביקים את `apps-script/Code.gs`.
3. בפונקציה `setApiKey_oneTime` מחליפים את המחרוזת למפתח אקראי ארוך (32 תווים ומעלה), מריצים אותה **פעם אחת** ומאשרים הרשאות.
   (אם עדיין לא הורצו: `oneTimeSetup_v3` ו-`oneTimeSetup_v4`, שמוסיפות את עמודות 29-32.)
4. **Deploy ← New deployment ← Web app**. *Execute as*: **Me**. *Who has access*: **Anyone**. מעתיקים את הכתובת שמסתיימת ב-`/exec`.
5. באתר: בסרגל התחתון **חיבור** ← מדביקים את הכתובת והמפתח ← **בדיקת חיבור** (אמורה להחזיר "החיבור תקין") ← **שמירה והפעלה**.
   אפשר גם לקבוע את הכתובת לכולם בקובץ `config.js` (`API_URL`). המפתח לא נשמר שם: כל דפדפן מזין אותו פעם אחת.

אחרי שינוי קוד בשרת: **Deploy ← Manage deployments ← עריכה ← New version**. עריכת הקוד בלבד לא משנה את מה שמוגש בכתובת `/exec`.

## 3. אבטחה

- רק הפעולות שב-`API_ACTIONS_` ב-`Code.gs` ניתנות לקריאה מרחוק, וכולן דורשות מפתח. אין הגשת HTML ואין `google.script.run`.
- הכתובת פתוחה לכולם ("Anyone"), ולכן המפתח הוא ההגנה היחידה. השתמשו במפתח אקראי ארוך ואל תשתפו אותו. מפתח שנחשף: להחליף ב-`setApiKey_oneTime`.
- המפתח נשמר ב-`localStorage` של הדפדפן שהזין אותו. לא לשמור אותו בקבצי האתר.
- קוד האתר ב-GitHub Pages גלוי לכל מי שיש לו את הכתובת (כולל התעריפים והנוסחאות). הנתונים עצמם נמצאים רק בגיליון.
- כתיבות לגיליון הלקוחות מתבצעות תחת נעילה (`LockService`) כדי למנוע דריסה בין מכשירים.

## 4. ייצוא Excel

- **server** (ברירת מחדל כשמחוברים): נוצר ב-Apps Script, עם צבעים וגרדיאנט. זה השימוש היחיד של Apps Script מעבר לקריאה/כתיבת נתונים (קובץ זמני ב-Drive שנמחק מיד).
- **client**: נוצר בדפדפן (SheetJS): ערכים ומיזוגים, **בלי צבעים**. מוגדר בחלון "חיבור".

## 5. מה לא כלול

- טופס הלקוח `Form.html` (הצפנה עם המפתח הציבורי של הפריסה) ואפליקציית המובייל: דורשים התאמה לארכיטקטורה הזאת.
- נתוני הדוגמה ב-`samples/` סינתטיים. התוצאות במצב דמו אינן כדאיות אמיתית.

## 6. בנייה מחדש מקבצי הייצור

```
python tools/build_site.py <תיקיית קבצי הייצור> .
```

התיקייה חייבת להכיל `Code.gs`, `Index.html`, `ConsumptionAnalysis.html`, `SystemSizing.html`, `FinancialModel.html`, `PrintQuote.html`. הסקריפט מזריק את המתאם לכל דף ומייצר מחדש את קבצי הדוגמה.

## 7. פתרון תקלות

| הודעה | סיבה | פתרון |
|---|---|---|
| "לא ניתן להגיע לשרת הנתונים" | כתובת שגויה, אין אינטרנט, או חסימת CORS | ודאו שהכתובת מסתיימת ב-`/exec` ושהפריסה *Anyone* |
| "תשובה שאינה JSON" | הפריסה דורשת התחברות גוגל או הכתובת שגויה | פריסה חדשה עם *Who has access: Anyone* |
| `unauthorized` | מפתח שגוי | להזין מחדש (האתר שואל פעם נוספת) |
| `not_configured` | לא הורצה `setApiKey_oneTime` | להריץ פעם אחת בעורך |
| ייצוא Excel בשרת איטי או נקטע | מגבלת 6 דקות ב-Apps Script | להפעיל Services ← Google Sheets API, או לעבור לייצוא `client` |
